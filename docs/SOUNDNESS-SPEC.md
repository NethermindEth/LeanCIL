# Specification baseline

LeanCIL models ECMA-335 6th edition (June 2012) as amended by the
[ECMA-335 augments](https://github.com/dotnet/runtime/blob/b22bfee2010118c58ae143c3b8a1aaee3d0c8c4c/docs/design/specs/Ecma-335-Augments.md)
that Microsoft maintains in dotnet/runtime, pinned at commit
`b22bfee2010118c58ae143c3b8a1aaee3d0c8c4c`. Where the two disagree, the augment is the
reference. Each augment area below is either modeled, rejected before or during checked
execution, or not applicable to the extracted semantics.

A model fault (`invalidState`, a memory fault or `unsupported`) is never a successful execution
and never a named CLR exception, so "rejected at execution" excludes the path from every proof.

| Augment area | LeanCIL status | Where enforced |
| --- | --- | --- |
| Signatures: TypeSpec after `CLASS`/`VALUETYPE` or a custom modifier | Rejected or not applicable. Mono.Cecil decodes signatures (a trusted component). The one admitted modifier must name a non-TypeSpec `System.Runtime` `InAttribute`. | [InReferences.cs:12-16](../Extractor/InReferences.cs) |
| Signatures: custom modifiers in more places, `BYREF` before modifiers | Rejected except `modreq(InAttribute)` directly before a modifier-free `BYREF` parameter. `BYREF CMOD T`, `modopt` and other `modreq` forms fail; locals, returns and fields with modifiers are unsupported types; typed contract signatures admit none. | [InReferences.cs:12-16](../Extractor/InReferences.cs), [MetadataValidation.cs:283-332](../Extractor/MetadataValidation.cs), [ContractMethodMetadata.cs:79-86](../Extractor/ContractMethodMetadata.cs); test [ConstrainedCalls.cs:210-244](../Tests/ConstrainedCalls.cs) (`nested`, `modopt`, `other-modreq`) |
| Heap sizes | Not applicable: metadata heaps are decoded by Mono.Cecil. | [Trusted components](SOUNDNESS.md#trusted-components-and-deployment-assumptions) |
| Metadata merging | Not applicable: the CLI does not merge metadata and LeanCIL reads one assembly per extraction. | - |
| Metadata logical format (InterfaceImpl order) | Not applicable: constrained resolution tests interface membership and rejects ambiguity, so declaration order cannot change the result. | [Dispatch.lean:91-115](../CIL/Extraction/Dispatch.lean) |
| Module initializer | Not modeled; static constructors, including `<Module>..cctor`, are never extracted. Methods on a type with a static constructor need `--assume-initialized`; a readonly static stored by any other module method, including a module initializer, is rejected. | [MetadataValidation.cs:428-431](../Extractor/MetadataValidation.cs), [StaticValues.cs:97-98](../Extractor/StaticValues.cs); [static initialization assumption](SOUNDNESS.md#trusted-components-and-deployment-assumptions) |
| Default interface methods | Rejected: a constrained slot must be abstract and implemented on the struct itself. | [Dispatch.lean:103](../CIL/Extraction/Dispatch.lean); test [ConstrainedEvidence.lean](../Tests/ConstrainedEvidence.lean) `default_interface_slot_rejected` |
| Static interface methods | Rejected: `constrained.` must precede `callvirt` on an instance slot; `constrained. call` and `constrained. ldftn` fail. | [Constrained.lean:39-41](../CIL/Extraction/Constrained.lean), [Dispatch.lean:94](../CIL/Extraction/Dispatch.lean), [ConstrainedCalls.cs:43-45](../Extractor/ConstrainedCalls.cs); test `static_virtual_slot_rejected` |
| Covariant return types | Rejected: class instance methods and unconstrained virtual dispatch are unsupported, and an interface override must match the slot signature exactly. | [MetadataValidation.cs:420](../Extractor/MetadataValidation.cs), [Dispatch.lean:109-110](../CIL/Extraction/Dispatch.lean) |
| Function pointer type identity | Stricter than the augment: only the default managed convention is callable, compared exactly; unmanaged conventions are rejected. | [Generics.lean:125-130](../CIL/Extraction/Generics.lean), [ManagedPointers.cs:32-33](../Extractor/ManagedPointers.cs) |
| `conv.ovf.<to>.un` with float source | Not reachable: values have no floating-point form, float constants and conversions are untranslated, and scalar flow requires an integer operand. | [Types.lean:42-61](../CIL/Types.lean), [IntegerArithmetic.lean:54-60](../CIL/IntegerArithmetic.lean), [InstructionTranslation.cs:278](../Extractor/InstructionTranslation.cs); `floatRaw` cases in [ScalarEvidence.lean](../Tests/ScalarEvidence.lean) |
| Ref fields | Rejected: a byref field type is unsupported. `Span<T>` and `ReadOnlySpan<T>` are runtime-modeled views, not structs with a ref field. | [MetadataValidation.cs:237-238](../Extractor/MetadataValidation.cs), [SpanViews.lean:14](../CIL/Safety/SpanViews.lean) |
| Managed pointers: null and one past the end | Modeled conservatively. Null is a managed-reference value that can be stored, passed and compared; dereferencing or offsetting it is a `nullDereference` model fault, not the augment's `NullReferenceException`. End positions form only as declared sentinels and grant no access. | [Memory.lean:52-54, 126-172](../CIL/Safety/Memory.lean), [InstructionMemory.lean:113-114, 969-974](../CIL/Safety/InstructionMemory.lean), [RuntimeExceptions.lean:15-19](../CIL/Safety/RuntimeExceptions.lean) |
| `RefSafetyRulesAttribute` (escaping `this`) | Not checked. The admitted subset has no `box`, so a struct receiver is always caller-owned storage and the boxing elimination the rule licenses cannot arise. | [OPCODES](OPCODES.md#unsupported-opcodes) |
| ByRefLike types in generics (`AllowByRefLike` 0x20) | Modeled: the flag is accepted and every generic method is checked as its closed instantiation. Byref-like elements cannot be heap array elements or fields of heap-storable structs. | [MethodSpecialization.cs:80-83](../Extractor/MethodSpecialization.cs), [Layout.lean:355](../CIL/Extraction/Layout.lean), [Arrays.cs:44](../Extractor/Arrays.cs) |
| Rules for IL rewriters (RVA alignment) | Not checked: `CreateSpan` data must be a local explicit-layout type with `.pack` 1, 2, 4 or 8, but RVA alignment to the element size is not validated, and the model does not raise the CLR's `ArgumentException` for a misaligned field. | [StaticData.cs:21-23](../Extractor/StaticData.cs), [StaticMemory.lean:46, 87-91](../CIL/Safety/StaticMemory.lean) |
| Checked user-defined operators | Not applicable: operators are ordinary calls resolved by token or exact runtime signature, never by name. | [RuntimeModels.cs](../Extractor/RuntimeModels.cs) |
| Atomic reads and writes | Not applicable: the model is single-threaded and `volatile.` is unsupported. | [SOUNDNESS](SOUNDNESS.md#what-verification-establishes) |
| Backward branch constraints (deleted) | Modeled: stack kinds come from a worklist over all reachable edges; every successor must see the same stack, and inconsistent joins are rejected. | [NativeOperands.cs:285-297](../Extractor/NativeOperands.cs), [Scalars.lean:850-893](../CIL/Extraction/Scalars.lean); tests [Loops.cs:558-587, 673-674](../Tests/Loops.cs) |
| Transient pointers | Modeled: `ldloca`/`ldarga` yield frame-owned references that expire at return. Unmanaged pointers share the reference representation, and conversion to integer addresses is rejected. | [Scalars.lean:38-45](../CIL/Extraction/Scalars.lean), [OPCODES](OPCODES.md#translated-opcodes) (`conv.u`, `ldloca`) |
| `newobj` for SZ arrays | Rejected: array constructors are external methods without a runtime model. | [MetadataValidation.cs:478-488](../Extractor/MetadataValidation.cs) |
| API documentation | Not applicable: runtime methods are admitted only through exact signature models. | [Runtime assumptions](SOUNDNESS-RUNTIME.md#runtime-assumptions) |
| Debug Interchange Format | Not applicable to semantics: Portable PDB supplies local names for proofs only. | [DebugNames.lean](../CIL/DebugNames.lean) |
| Extended layout (0x18) | Rejected: aggregates must be sequential or explicit, enums and value tuples auto. This relies on Mono.Cecil's masked layout flags. | [MetadataValidation.cs:198](../Extractor/MetadataValidation.cs), [EnumTypes.cs:60](../Extractor/EnumTypes.cs) |
| Implicit argument coercion (int32 to `native unsigned int`) | Rejected: no implicit int32-to-native coercion exists. Call arguments, `stloc`, `starg` and `ret` require the slot's kind, and checked stores into eight-byte homes require an `i64`. Code needs an explicit `conv.i` or `conv.u`. | [Scalars.lean:63-67, 760-804](../CIL/Extraction/Scalars.lean), [Frames.lean:90-103](../CIL/Safety/Frames.lean), [InstructionMemory.lean:259-268, 712-718](../CIL/Safety/InstructionMemory.lean); tests `no_implicit_native_coercion`, `native_home_rejects_int32` |
| Init-only static fields | Modeled: `stsfld` is never extracted, and a readonly value is admitted only when its own static constructor is the sole writer. Writes by unmodeled code are an explicit assumption. | [InstructionTranslation.cs:227](../Extractor/InstructionTranslation.cs), [StaticValues.cs:97-98](../Extractor/StaticValues.cs); test [StaticValues.cs:221-224](../Tests/StaticValues.cs) |

Mixed native/int32 binary operands are widened under III.1.5, not III.1.6, and are listed in
[opcode coverage](OPCODES.md#translated-opcodes).
